# Nachprüfung R1: Ladezustand im Aufgabenpanel

Stand: 26.10.2026. Branch `feat/bedienkonzept-20261026`.
Ausgangspunkt: `e4ac18a`. Kein produktiver Versionswechsel, Push oder Release.

## Ursache und Korrektur

Die vorhandene ID-Abfrage löste Aufgaben bereits unabhängig von der Listenseite
auf. Das Panel behandelte jedoch jede noch fehlende Antwort als fehlende Aufgabe
und verwendete zusätzlich einen Listeneintrag als Ausweichantwort.

`frontend/src/workspace/ReviewWorkspace.tsx` enthält jetzt ein eigenes, nach
Aufgaben-ID geschlüsseltes `ReviewTaskPanel`. Es verwendet unverändert den
bestehenden lesenden Vertrag `POST /api/v1/workspace/review/query` mit `task_id`.
Kein neuer Endpunkt, keine Berechtigungs- oder Fachregeländerung.

| Zustand | Darstellung |
| --- | --- |
| Initial / erste Anfrage läuft | „Prüfaufgabe: Ladevorgang läuft.“; kein Nicht-gefunden-Hinweis und keine Aufforderung zur Listenaktualisierung |
| Erfolgreiche ID-Antwort mit Aufgabe | Angeforderte Aufgabe mit bestehendem Kontext und Aktionen |
| Erfolgreiche ID-Antwort ohne Aufgabe | „Prüfaufgabe nicht gefunden“; Hinweis auf den abgefragten Datenstand, Filter bleiben erhalten |
| API-Fehler | Eigene Fehlermeldung im Panel und „Erneut versuchen“ für dieselbe ID; kein fachlicher Leertreffer |
| Erneutes Laden bei vorhandenem Stand | Bestehendes Ressourcenmuster mit Zeitstempel und vorherigem Stand; Kontextaktionen bei veralteter Antwort gesperrt |

Beim ID-Wechsel wird das vorherige Panel abgebaut; dessen Anfrage wird über
das bestehende Abort-/Antwortversionsmuster verworfen. Eine alte Aufgabe darf
nicht als Ergebnis einer neuen ID erscheinen. Filter, Seite, URL und Rückweg
werden durch diese Änderung nicht zurückgesetzt.
