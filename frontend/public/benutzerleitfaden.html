1. Start und Einrichtung

Unter Hilfe & Anleitungen stehen durchsuchbare Arbeitsablaeufe, haeufige Fragen und Begriffserklaerungen. Hilfe zum Bereich oeffnet das passende Thema in einem neuen Tab und erhaelt ungespeicherte Eingaben. Fragezeichen-Hilfen funktionieren per Maus, Tastaturfokus und Touch; Escape schliesst sie. Die Ablaufnavigation markiert nur den aktuellen Bereich, keine erledigte fachliche Pruefung.

  1. Oeffnen Sie die Adresse Ihrer Installation. Die Standard-Compose-Konfiguration ist auf dem Server unter http://127.0.0.1:8010/ erreichbar. Bei einer LAN-Installation verwenden Sie die vom Betreiber eingerichtete Adresse.
  2. Oeffnen Sie Einrichtung in der Navigation. Fuer eine neue Installation sind keine Konten, Wallets oder Boersen-Schluessel vorbelegt.
  3. Pruefen Sie zuerst Installation: privater Datenpfad, Schreibrechte und Secret-Vault. Im Demo-/Testmodus sind Speichern und externe Abrufe absichtlich gesperrt. Backend erreichbar bestaetigt nur die interne API, nicht einen Boersenzugang.
  4. Tragen Sie nur Ihre tatsaechlich verwendeten Wallets und Zuordnungen ein. Nicht verwendete Quellen und optionale Dienste bleiben leer.
  5. Speichern Sie die Konfiguration. Wenn die Anwendung einen Neustart verlangt, starten Sie API beziehungsweise Container neu. Damit werden Konto- und Dateizuordnungen aktiv; dies importiert noch keine Historie.
  6. Fuer einen reinen Dateiimport brauchen Sie keine Boersen-API-Schluessel. Zugangsdaten werden nur fuer entsprechende externe Abrufe benoetigt.

Die Anwendung besitzt keine globale Benutzeranmeldung. Netzwerkfreigabe, Zugriffsschutz und Sicherungen sind Aufgabe des Betreibers. Geben Sie die Anwendung nicht ungeschuetzt im Internet frei. Speichern Sie Schluessel nicht im Quellcode oder in weitergegebenen Unterlagen.

2. Unterlagen vorbereiten

Sammeln Sie fuer jede Quelle die Originalexporte: Handelsdaten, Ein- und Auszahlungen, Gebuehren sowie gegebenenfalls Rewards, Staking und Derivate. Fuer FIFO kann auch Historie vor dem gewuenschten Steuerjahr erforderlich sein. Eine heutige Bestandsaufnahme ersetzt diese Historie nicht.

  • Originaldateien unveraendert und ausserhalb der Anwendung sichern. Eine Vorschau oder JSON-Belegspur ist keine vollstaendige Sicherung der Originaldatei.
  • Dateien einer Boerse oder eines Exporttyps gemeinsam auswaehlen. Fuer andere Quellen einen neuen Importvorgang beginnen.
  • ZIP-Archive vor dem Import lokal entpacken. PDF-Abrechnungen, Screenshots und Wallet-Sicherungsdateien sind keine CSV-/Excel-Transaktionsdateien.
  • Die gleiche Transaktion kann in mehreren Exporten vorkommen. Ein identischer Datei-Hash erkennt keine beliebigen inhaltlichen Ueberschneidungen zwischen unterschiedlichen Exporten. Solche Faelle bleiben anhand der Belegspuren zu pruefen.

3. Dateien importieren

  1. Oeffnen Sie Daten importieren, dann Dateiimport.
  2. Waehlen Sie die passende Quelle. Die Quellenliste stammt aus den vorhandenen Importprofilen. Waehlen Sie nicht eine andere Boerse, nur um eine Dateipruefung zu umgehen.
  3. Klicken Sie Dateien auswaehlen oder ziehen Sie Dateien in den Auswahlbereich. Mehrere Dateien sind moeglich: bis zu 20 Dateien, 25 MB je Datei und 100 MB insgesamt pro Vorgang.
  4. Klicken Sie Dateien pruefen. Dieser Schritt erzeugt noch keinen Import und fuehrt keine Boersenabfrage aus.
  5. Kontrollieren Sie je Datei den Status, die Zeilen, das Profil, den SHA-256-Hash und bei Excel das Tabellenblatt. Mit Vorschau sehen Sie eine Stichprobe der ersten Zeilen.
  6. Nach einer Aenderung von Quelle oder Tabellenblatt ist eine neue Pruefung erforderlich.

Die Auswahl und Vorschau liegen waehrend dieses Vorgangs im Browser. Erst der ausdruecklich freigegebene Import schreibt Rohdaten und startet deren Verarbeitung. Lassen Sie die Seite waehrend eines Imports geoeffnet.

4. Vorschau und Dateipruefung

StatusBedeutung und naechster Schritt
UngeprueftDatei auswaehlen, Quelle kontrollieren und die Pruefung starten.
ImportierbarDer Parser kann die benoetigten Spalten lesen. Das ist noch keine steuerliche Freigabe oder Bestaetigung der Vollstaendigkeit.

Der angezeigte SHA-256-Wert bezieht sich bei hochgeladenen Dateien auf die Originalbytes, auch bei CSV mit UTF-8-BOM. Bei Excel gehoert zur Importidentitaet zusaetzlich das gewaehlte Tabellenblatt. Eine umbenannte, ansonsten identische Datei bleibt daher als Dublette erkennbar.

Vorhandene Referenz- oder Sammelplattformdaten sind nicht automatisch eine zweite primaere Historie. Achten Sie besonders bei mehreren Exportquellen auf doppelte Trades, interne Transfers und bereits abgedeckte Zeitraeume.

5. Import freigeben und Ergebnis kontrollieren

  1. Setzen Sie nach der Pruefung den Haken bei Gepruefte Dateien freigeben. Die Zahl gibt die aktuell importierbaren Dateien an. Dubletten und blockierte Dateien werden nicht mitimportiert.
  2. Klicken Sie auf die Schaltflaeche Datei(en) importieren. Die Dateien werden nacheinander verarbeitet. Starten Sie nicht parallel denselben Import in einem zweiten Fenster.
  3. Der Status Importiert zeigt den bestaetigten Import. Angezeigt werden Rohzeilen, normalisierte Ereignisse und nicht zugeordnete Zeilen. Diese Zahlen koennen voneinander abweichen: etwa, wenn ein Trade mehrere Ereignisse erzeugt oder eine Zeile nicht zugeordnet werden kann.
  4. Laden Sie bei Bedarf ueber Belegspur den JSON-Nachweis mit Import-Batch, Dateifingerabdruck, Rohzeilen und abgeleiteten Ereignissen herunter.
  5. Im Importverlauf finden Sie die gespeicherten Dateien und deren Verarbeitungsstatus. Mit Neuer Import leeren Sie nur die Browserauswahl, nicht gespeicherte Importe.
  6. Oeffnen Sie anschliessend Hinweise pruefen und danach das betreffende Steuerjahr. Ein erfolgreicher Import bedeutet nicht, dass bereits alle Preis-, FIFO- oder Belegfragen abgeschlossen sind.

Der bestaetigte Import startet auch die vorhandene Verarbeitungspipeline und aktualisiert abgeleitete Auswertungen. Eine archivierte Abgabe ist davon zu unterscheiden. Bestehende Abgabestaende nicht durch einen neuen Bericht ersetzen; Aenderungen anhand der Nachweise pruefen.

6. Formate und CSV-Vorlage

Der normale Dateiimport akzeptiert CSV, XLSX und XLS. CSV muss UTF-8 sein; UTF-8-BOM sowie Komma und Semikolon als Trennzeichen werden unterstuetzt. Das Profil muss zum Spaltenlayout des Exports passen. Ein PDF wird durch Umbenennen in CSV nicht importierbar.

Ja, ein passendes Tabellenlayout ist erforderlich. Die ausfuehrliche Importformat-Referenz mit Pflichtfeldern, Spaltennamen und Beispielen je Quelle ist auch als PDF verfuegbar. Im Importdialog oeffnet Formate & Spalten direkt den Abschnitt zur gewaehlten Quelle. CSV-Vorlage laedt deren leere Kopfzeile; Excel-Vorlagen laedt eine Arbeitsmappe mit sieben leeren Vorlagenblaettern. Waehlen Sie nach dem Befuellen dieselbe Quelle und das dazugehoerige Blatt.

Quelle / VorlageKonkretes Beispiellayout (Kernspalten)

Binance / VorlageUTC_Time, Account, Operation, Coin, Change
Bitget / VorlageTimestamp UTC+8 (Completion), Coin, Quantity, Type
Pionex / Vorlagetime, coin, change, type

Die Kernspalten sind nicht alle Pflicht fuer die technische Erkennung: erforderlich sind Zeitpunkt, Asset oder eine unterstuetzte Ableitung und Menge. Ereignisart, Handelsgegenwerte, Gebuehren und Belegkennungen sind fuer die weitere Auswertung wesentlich. Die Referenz nennt die alternativen Spaltennamen und Sonderlayouts. Beliebige Solscan-CSV-Dateien und rohe RPC-JSON-Antworten sind nicht pauschal unterstuetzt. Ohne explizite Zeitzone nimmt Bitget UTC+8 an; eigene normalisierte Daten daher vorzugsweise mit ISO-Zeitstempel und Offset erfassen.

Verwenden Sie Originalexporte fuer die vorhandenen Profile, beispielsweise Binance, Bitget, Pionex, Coinbase und Helium. Spezielle Onchain-Exporte muessen zum entsprechenden vorhandenen Profil passen. Eine Quelle ist nicht allein deshalb unterstuetzt, weil ihr Name aehnlich klingt. Sammelplattformen wie Blockpit werden im normalen Dateiimport nicht als weitere primaere Handelshistorie angeboten; solche Unterlagen separat als Referenz aufbewahren und nicht ueber eine fremde Quelle erzwingen.

Die herunterladbare CSV-Vorlage ist absichtlich leer und enthaelt keine Beispieltransaktionen. Fuer eigene, belegte Eintraege waehlen Sie die Quelle Manuelles CSV:

time,asset,amount,type,quote_asset,quote_quantity,fee_asset,fee_quantity,account,tx_id
SpalteInhalt
timeBelegter Zeitpunkt; vorzugsweise ISO-8601 mit Zeitzone, zum Beispiel das Format JJJJ-MM-TTThh:mm:ssZ.
asset / amountAsset-Kuerzel und belegte Menge. Dezimalwerte eindeutig, vorzugsweise mit Punkt, ohne Tausendertrennzeichen.
typeBelegte Ereignisart, etwa deposit, withdrawal, buy, sell oder reward; nicht allein aus einem positiven Betrag auf Einkommen schliessen.
quote_asset / quote_quantityGegenasset und Gegenmenge eines Handels, sofern im Beleg vorhanden.
fee_asset / fee_quantityBelegte Gebuehr und deren Asset.
account / tx_idNachvollziehbare Kontozuordnung und urspruengliche Transaktionskennung.

Die reine Kopfzeile ist nicht importierbar. Ergaenzen Sie nur belegte Daten. Unterschiedliche Dezimal-, Zeit- oder Vorzeichenkonventionen nicht ungeprueft umdeuten; nach der Vorschau auch die erzeugten Ereignisse kontrollieren.

7. API-Abgleich und weitere Quellen

Transaktionshistorie der ausgewaehlten Quelle abrufen

  1. Unter Quellen & Wallets die konkrete Wallet oder einzelne Boersenverbindung oeffnen und Transaktionen abrufen waehlen.
  2. Zeitraum einschliesslich frueherer Anschaffungen einstellen. Binance und Pionex benoetigen die tatsaechlich gehandelten Paare. Solana wird ohne Assetfilter abgerufen, damit Gegenbewegungen und Gebuehren nicht fehlen.
  3. Bei Solana ausdruecklich Oeffentlicher RPC (Free) ohne gespeicherte API-Keys oder Eigener Anbieter (Free/Premium) waehlen. Beim eigenen Anbieter einen eingerichteten Helius-, Alchemy- oder Custom-RPC auswaehlen. Ein Key ist kein Premium-Tarifnachweis und erhoeht keine Quote automatisch. Anbieterlimits und moegliche Kosten pruefen.
  4. Die externe Anfrage bestaetigen und Vorschau abrufen waehlen. Originalrecords und Fortsetzungscursor werden privat gesichert. Eine isolierte Kopie berechnet die Vorschau; noch keine produktiven Finanzdaten werden geaendert.
  5. Neue Datensaetze, Duplikate, Stichprobe, Abdeckung und Vorher-/Nachherstand pruefen. Freigebende Person eintragen, Import und Neuberechnung getrennt bestaetigen. Erst Importieren und neu berechnen uebernimmt diese unveraenderte Vorschau atomar.
  6. Danach Hinweise und Steuerjahr pruefen. Importfreigabe ist keine steuerliche Quellenaktivierung oder Jahresfreigabe. Der eingetragene Name ist keine technische Identitaetspruefung.

Neue Solana-Auftraege bleiben fest an ihre gewaehlte Anbietereinrichtung gebunden. Fortsetzen verwendet diese Bindung; eine andere Auswahl im Startformular aendert den bestehenden Auftrag nicht. Geaenderte Keys oder URLs werden nicht still uebernommen. Ein Anbieterwechsel erfordert einen neuen Auftrag, ein Fehler fuehrt zu keinem automatischen Ersatzanbieter. Fuer aeltere Auftraege ohne gespeicherte explizite Bindung wird kein nachtraeglicher Anbieter-Pin behauptet.

Signaturinventar und Restzeit

  1. Signaturliste ermitteln: Zuerst werden verfuegbare finalisierte Signaturreferenzen inventarisiert. Bis zum Inventarabschluss bleiben eindeutige Gesamtzahl, Gesamtprozentsatz und Restzeit unbekannt. Gefundene Referenzen sind noch keine abgerufenen Transaktionsdetails.
  2. Transaktionsdetails abrufen: Nach Abschluss wird die eindeutige Liste abgearbeitet. Mehrfachfunde ueber mehrere Adressen zaehlen nicht als mehrere Transaktionen. Eine ETA benoetigt mindestens fuenf erfolgreich gemessene Detailabrufe, aktuelle Messdaten und verfuegbare effektive Limitdaten. Die geglaettete gemessene Rate bleibt durch die gemeinsamen Limits begrenzt; Warte-/Retryzeiten erfolgreich gespeicherter Detailseiten gehen in deren Messung ein.

Die Restzeitschaetzung gilt nur fuer verbleibende verfuegbare Transaktionsdetails, nicht fuer die gesamte Bearbeitung. Discovery, Pause, Abbruch und Fehler haben keinen laufenden Countdown. Bei Anbieterpausen, fehlenden oder veralteten Messdaten beziehungsweise fehlgeschlagener Statusaktualisierung wird keine verlaessliche laufende ETA behauptet. Die nachfolgende Vorschauberechnung hat keine ETA. Ein beendeter Detailabruf ist noch keine Importfreigabe. Auch 100 Prozent der verfuegbaren Details beweisen keine vollstaendige Wallet-Historie.

Detailanfragen bleiben sequenziell. Hoehere Tarif-/Parallelitaetswerte erzeugen keine zusaetzlichen Detailworker. RPC-Retention, geschlossene historische Tokenkonten und Eigentuemerwechsel bleiben Abdeckungsgrenzen; fehlende Belege gegebenenfalls mit Originalexporten ergaenzen.

Der gestartete Serverauftrag kann bei geschlossenem Browser weiterlaufen. Pausieren, ausdrueckliches Fortsetzen und Auftrag abbrechen erhalten bereits gesicherte Originalbelege. Nach Serverneustart erfolgt kein stiller Wiederanlauf. Fehlerhafte Seiten verschieben den Cursor nicht; ein Daten-/Methodenwechsel sperrt eine veraltete Vorschau. Hoechstens zwei aktive Abrufe und 100 gespeicherte Auftraege; Datensatzlimit bei Bedarf beim Fortsetzen erhoehen.

Oeffentliche Solana-Adresse hinzufuegen

Nach erfolgreichem Bestandsabruf zeigt Quellen & Wallets > Quelle > Bestaende die gespeicherten Tokenmengen auch ohne EUR-Kurs oder Historie. Das Dashboard fuehrt direkt dorthin. Unbekannter EUR-Wert ist kein Nullbestand; 0 importierte Ereignisse ist kein Beweis fuer einen fehlgeschlagenen Bestandsabruf. Historie, Anschaffungswerte und Steuerberechnung bleiben getrennt. Nach Aenderung der Profil-RPC-URL den Neustarthinweis beachten.

Der ausdrueckliche Bestandsabruf einer zugeordneten Profilwallet nutzt Solana-RPC auch ohne Alchemy-Key. Gespeicherte Alchemy-/Helius-Zugaenge werden beruecksichtigt. Oeffentliche RPCs koennen Anfragen begrenzen; fuer regelmaessige Abrufe einen eigenen Anbieter einrichten. Unter Hinweise / Abgleich stehen konkreter Abruffehler und Einrichtungseinstieg. Fehlende oder unvollstaendige Antworten sind kein Nullbestand; ein alter Erfolgsstand bleibt bei spaeterem Fehler erhalten. Der oben beschriebene Historienauftrag ist davon getrennt und verwendet auch weitere gespeicherte Beobachtungsadressen exakt.

  1. Quellen & Wallets > Quelle hinzufuegen > Solana Wallet oeffnen.
  2. Eingabeart Oeffentliche Adresse speichern beibehalten.
  3. Optional einen Namen und die oeffentliche Adresse eingeben.
  4. Weiter, Zusammenfassung pruefen und Adresse speichern waehlen.

Dafuer sind weder Signatur noch Einrichtungspasswort oder Wallet-Verbindung erforderlich. Adressen erscheinen einzeln in der Quellenliste; erneutes Speichern erzeugt keinen zweiten Eintrag. Bestehende Pruefungen bleiben erhalten. Speichern startet keinen Abruf oder Historienimport und aktiviert keine Steuerquelle. Anschliessend Transaktionen abrufen fuer die konkrete Adresse verwenden; ein Bestandsabruf setzt weiterhin die entsprechende Profil-/Anbieterkonfiguration voraus.

Optionaler Wallet-Eigentumsnachweis

Unter Einrichtung > Wallet-Eigentumsnachweis wird der lokale Zugang geprueft. Neue Docker-Installationen bereiten ein zufaelliges Einrichtungspasswort vor. Bestehende Installationen werden durch ein Update nicht still freigeschaltet. In der privaten Betreiberkonsole gegebenenfalls ausdruecklich vorbereiten und anschliessend lokal anzeigen:

docker compose -f compose.ghcr.yml exec steuerreport python -m steuerreport_v2.connector_setup status
docker compose -f compose.ghcr.yml exec steuerreport python -m steuerreport_v2.connector_setup init
docker compose -f compose.ghcr.yml exec steuerreport python -m steuerreport_v2.connector_setup show-token

init ersetzt keine vorhandenen Passwoerter oder Vault-Schluessel und importiert keine Finanzdaten. show-token funktioniert nur in einer privaten interaktiven Konsole, nicht mit Pipe oder -T. Bei einem manuell gestarteten Container docker exec -it CONTAINERNAME verwenden; nativ python3 -m steuerreport_v2.connector_setup mit denselben Unterbefehlen. Das Passwort niemals in Chat, URL, Diagnoseexport oder Screenshot weitergeben.

Unter Quellen & Wallets > Quelle hinzufuegen > Solana-Wallet > Optional: Eigentum per Signatur nachweisen die oeffentliche Adresse und das Einrichtungspasswort in Connector-Setup-Token eingeben. Dann eine Challenge anfordern und exakt deren Nachricht mit einem vertrauenswuerdigen Wallet-Signer signieren, nicht als Transaktion. Die oeffentliche Base58-Signatur einfuegen und pruefen lassen. Ein automatisches Phantom-Signierfenster ist derzeit nicht enthalten. Niemals Wallet-Private-Key oder Seed eingeben.

Das Passwort schuetzt Connector-Administration, unter anderem Nachweise und Geraetekopplung; es ist kein Boersen-API-Schluessel. Die Web-API gibt es nicht aus. Bei 401/403 den Zugang pruefen, bei 503 die lokale Vorbereitung. Vor Updates auch /state/keys/connector-setup.token sichern. Eine bestaetigte Signatur aktiviert keine steuerliche Quelle und ersetzt keine Importhistorie.

Version und Updates

Die Versionsanzeige im Kopfbereich oeffnet Einrichtung > Version & Updates. Waehlen Sie stabile Versionen oder zusaetzlich RC. Automatik ist anfangs aus und wird erst mit Einstellungen speichern uebernommen. Jetzt pruefen liest oeffentliche GitHub-Release-Metadaten, keine Finanzdaten. Manuell gilt mindestens eine Minute Wartefrist, automatisch hoechstens alle sechs Stunden im geoeffneten Browser. Der lokale Statusabruf allein fragt GitHub nicht ab.

Waehlen Sie ein konkretes Release und kopieren Sie den KI-Updateauftrag oder laden Sie TXT/JSON. Bei fehlender Zwischenablage wird der vollstaendige Text zur manuellen Auswahl angezeigt. Das Ziel bleibt an Release-ID und Metadatenhash gebunden. Ein neueres Release ersetzt es nicht automatisch. Unbekannte Quellcommits, Image-Digests und Registry-Zugriff muessen vor einem gesonderten Update geprueft werden. Kein Button installiert Software, startet eine KI oder korrigiert Finanzdaten.

Boersenkonten und Datenanbieter

Unter Einrichtung > Eigene Verbindungen koennen mehrere benannte Konten derselben Boerse getrennt angelegt werden. Unterstuetzt sind Binance, Bitget, Pionex und Coinbase. Bitget benoetigt zusaetzlich eine Passphrase; Coinbase verwendet den fuer den Connector vorgesehenen CDP-Key-Namen und ECDSA-Schluessel. Nur Lesezugriffe benoetigen, keine Handels- oder Auszahlungsrechte freigeben. Nicht verwendete Boersen brauchen keine Zugangsdaten.

  1. Anbieter und Kontonamen waehlen, Zugangsdaten erfassen und ausdruecklich speichern. Ohne verfuegbaren Vault gibt es keinen Klartext-Ersatz.
  2. Leere Secret-Felder behalten bestehende Werte; Zugangsdaten entfernen ist eine eigene bestaetigte Aktion.
  3. Optional Verbindung testen: authentifizierter Lese-Endpunkt, keine vollstaendige Berechtigungspruefung und kein Historienimport.
  4. Bestand abrufen: ausdruecklicher externer Abruf mit verbindungseigenem Snapshot. Herkunft, Eigentum und fachliche Aktivierung bleiben unter Quellen & Wallets getrennt zu pruefen.

Die bestehende Aktion Live abfragen fuer alte Einzelzugaenge bleibt in den erweiterten Einstellungen. Auch sie importiert nicht automatisch die vollstaendige Handelsgeschichte aller Boersen. Historische Kaeufe und Verkaeufe muessen ueber die tatsaechlich unterstuetzten Historienpfade oder Dateiimporte belegt werden.

Unter Einrichtung > Abrufsteuerung begrenzen Sekunden-, optionale rollierende 10-Sekunden- und Minutenfenster, Burst, Parallelitaet, Zeitlimits und Retries gemeinsam die ausgehenden Anfragen. Mehrere Konten teilen weiter ihre Anbieter-/IP-Budgets. Lokale Nutzung ist keine gemessene Herstellerrestquote; unbekannte Tarifgrenzen bleiben unbekannt. Wartegruende und Anbieterpausen stehen in der lokalen Budgetauslastung. Automatische Sync-Zeitplaene und Tages-/Monatsbudgets sind noch nicht aktiv. Ansicht aktualisieren liest bestehende Daten neu und ersetzt keinen bestaetigten Anbieterabruf.

Solana Free und eigene Abrufgeschwindigkeit

Im Feld Limitprofil stehen Alchemy, Helius, eigener Solana-RPC und Solana Public RPC direkt zur Auswahl. Fehlt ein eigenes Profil, sehen Sie ausdruecklich die geerbten Standardwerte. Erst Limitprofil speichern legt es an. Mit Gemeinsames IP-Limit bearbeiten erreichen Sie das zusaetzlich wirkende IP-Profil. Requests/s, Minutenlimit, Burst und Parallelitaet bleiben getrennte Grenzen.

Alchemy: CU/s sind keine Requests/s. 500 Compute Units/s nicht als 500 Requests/s eintragen; Methoden verbrauchen unterschiedlich viele CU. Dieses Formular bietet Requestprofile und lokale Kosten pro Minute, keinen eigenen CU/s-Limiter. Den eigenen Tarif anhand der Alchemy-Dokumentation pruefen. Bei Helius RPC- und DAS-/Enhanced-API-Limits nicht vermischen. Kein API-Key und keine Profilauswahl erhoeht automatisch Quoten oder startet einen Abruf.

Die Anbieterwahl im Historienauftrag erhoeht keine Limits. Massgeblich sind alle gemeinsam passenden IP-, Anbieter-, Methoden- und weiteren konfigurierten Budgets; die strengste wirksame Grenze kann auch einen Premium-Zugang begrenzen. Die Anzeige der effektiven Limits und Wartegruende ist lesend und keine Herstellerrestquote. Nicht verfuegbare Limitdaten bedeuten unbekannt, nicht unbegrenzt.

  1. In der Abrufsteuerung die Voreinstellung Solana Public RPC - Free mit Quelle, Pruefdatum, betroffenen Gruppen und moeglichen Konflikten pruefen.

Danach den externen Abruf bestaetigen und Kurse abrufen und Vorschau berechnen waehlen. Ohne automatische Fortsetzung jeden weiteren Abschnitt bewusst bestaetigen.
  7. Bereits belegte Preise und Wechselkursbelege bleiben in der kombinierten Vorschau erhalten. Budgetende, Fehler oder fehlender Fortschritt stoppen die automatische Folge. Offene Abrufe erneut versuchen ist eine eigene bewusste Wiederholung fehlgeschlagener Abfragen, keine Endlosschleife. Ein erreichtes Gesamtbudget wird beim Fortsetzen nicht zurueckgesetzt.

Ein Ansichtswechsel stoppt weitere automatische Abschnitte, nicht notwendig den schon laufenden Serverabschnitt. Ein unterbrochener Servervorgang ohne fertige Vorschau erfordert eine ausdrueckliche neue Planung; erhaltene Belege werden nicht geloescht.
  10. Nach Abschluss der Abrufabschnitte freigebende Person eintragen; Preise und Neuberechnung getrennt bestaetigen. Erst Preise und Neuberechnung uebernehmen schreibt den produktiven Preis-/Berechnungsstand. Fehlgeschlagene und blockierte Preise bleiben offen. Keine automatische Jahresfreigabe.

Der gesamte Ablauf ist ohne KI und Terminal bedienbar. Preise sind Tagesreferenzen, keine Einnahmen oder belegten Ausfuehrungskurse. Preisvorschauen rechnen ausschliesslich die eingefrorenen Canonical Events neu: keine Rohnormalisierung, keine neue Reward-/Trade-Zuordnung. Ein Preis kann dennoch Anschaffungskosten, Flows, Lots und Steuerbetraege veraendern; deshalb ist die Vorschau zu pruefen.

CoinGecko liefert historische EUR-Tagesreferenzen, sofern im Zugang verfuegbar. DefiLlama-USD-Kurse werden mit historischen EZB-USD/EUR-Referenzkursen ueber Frankfurter v2 umgerechnet. Gefundene Tagespreise schliessen keine offenen Klassifizierungsfragen und belegen keine vollstaendige Historie. Wofuer ist die KI zu gebrauchen? Der KI-Einsatzleitfaden beschreibt Textaufgaben und den neuen Modus Datenkorrekturen mit ausgewaehlten Datenbankzeilen, Vorschau, menschlicher Freigabe und Audit; er ist auch als PDF verfuegbar. Es gibt keinen unbeschraenkten Datenbank-, Datei- oder Wallet-Zugriff.

OpenRouter

  1. Waehlen Sie OpenRouter (Cloud). Die API-Basisadresse ist https://openrouter.ai/api/v1, nicht die Startseite von OpenRouter.
  2. Hinterlegen Sie Ihren eigenen OpenRouter-API-Key im Passwortfeld. Ein vorhandener Wert wird nicht zurueckgegeben; ein leeres Feld behaelt ihn beim Speichern bei. Ein neuer Wert ersetzt ihn.   3. Aktivieren Sie Cloud-Zugriffe erlauben und speichern Sie die KI-Einstellungen. Es wird noch kein Modell aufgerufen. Die Modell-ID darf fuer den ersten Modellabruf noch leer sein.
  4. Klicken Sie Modelle laden. Dabei wird ausschliesslich die Modellliste beim Anbieter abgefragt, keine Steuerhistorie uebermittelt. Im Feld Modell erscheint eine sichtbare Auswahlliste. Die exakte ID wird automatisch in Modell-ID uebernommen; dieses Feld bleibt fuer eigene IDs editierbar.
  5. Klicken Sie Verbindung testen. Dieser Aufruf verwendet einen festen neutralen Testtext ohne Steuerdaten und standardmaessig hoechstens 128 Antworttoken. Fuer Reasoning-Modelle kann unter Modellparameter das Testlimit bis 2048 erhoeht werden, weiterhin begrenzt durch das Antwortlimit. Ein erfolgreicher Test zeigt die tatsaechlich gemeldete Modell-ID und sichtbare Antwort an. Auch ein Test kann abgerechnet werden; Guthaben, Limits und Preise im eigenen OpenRouter-Konto pruefen.

Aktuelle Schnittstellenbeschreibung: OpenRouter Quickstart und Modellliste. Es wird kein bezahltes Modell automatisch ausgewaehlt und kein alternatives Modell nach einem Fehler still verwendet.

Free und Preise: Die Kennzeichnung verwendet die bei der Abfrage veroeffentlichten Textpreise: Eingabe, Ausgabe und ein ausgewiesener Anfragepreis muessen null sein. Sie ist eine Momentaufnahme des Katalogs, keine Preisgarantie fuer die Zukunft. Lokaler Server

Waehlen Sie Lokaler OpenAI-kompatibler Server, tragen Sie seine vom API-Container erreichbare Basisadresse und Modell-ID ein und aktivieren Sie Lokale KI aktivieren.
